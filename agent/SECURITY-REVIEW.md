# Security Review

审查对象：`D:\AgentProject\agent`

审查日期：2026-10-18

审查文件：`AgentState.py`、`AuditLog.py`、`CallModel.py`、`Execute_Tool.py`、`ModelClient.py`、`Skills.py`

## 结论

当前代码已具备一组较完整的纵深防御措施：工具白名单与读写权限分组、JSON 参数校验、工作区路径约束、补丁预览和显式确认、补丁验证与回滚、模型请求错误收敛、输入及上下文脱敏，以及对工具结果的“不可信数据”标记。

未发现可直接确认的任意命令执行、明显路径穿越、危险反序列化或未授权网络监听问题。仍有以下需要持续关注的风险：外部模型数据传输、天气服务的查询参数密钥、工具结果导致的提示注入，以及子进程调用和补丁操作的权限边界。

## Existing Controls

### 输入、凭据和模型边界

- `sanitize_prompt()` 限制输入长度，拒绝控制字符，并对常见 API key、密码、token 模式执行基础脱敏。
- 工具结果进入模型上下文前会经过 `_redact_for_context()`，并限制最大长度。
- 模型端点必须是有效的 HTTP(S) URL，禁止在端点中包含用户名、密码、查询参数或片段。
- API key 从环境变量读取，不写入工具定义，不随普通工具参数打印。
- 启动时会提示用户：输入和必要的工具结果可能发送到配置的外部模型服务。

### 工具调用和权限

- `Execute_Tool.py` 仅允许调用注册在 `TOOL_FUNCTIONS` 中的工具。
- 工具参数必须是 JSON 对象，并受工具定义和长度限制约束。
- 工具被划分为 `read` 和 `write` 权限组；写工具包括 `apply_patch`、`rollback_patch`、`create_task` 和 `update_task`。
- 工具执行错误对外返回通用错误信息，避免直接泄露内部异常和密钥。
- 工具结果被明确标记为外部、不可信数据，不能覆盖系统提示或产生新的系统级指令。

### 文件、网络和变更控制

- 相对路径通过 `_safe_workspace_path()` 解析到配置工作区，并拒绝越出工作区的路径。
- 网页抓取只允许公开 HTTP(S) 地址，并拒绝本机、回环、私有地址和不安全的重定向目标。
- 补丁应用前支持预览和校验；实际应用要求显式确认。
- 应用补丁后执行质量检查，失败时支持回滚。
- `StateMachine` 拒绝非法状态转换，例如禁止从 `IDLE` 直接进入 `APPLYING`，也禁止从 `APPLYING` 直接进入 `COMPLETED`。
- 子进程调用使用 `shell=False`，并设置受限环境及超时。

## Recommended Remediation

1. **移除 URL 中的天气密钥**
   - 如果天气服务支持，改用请求头认证。
   - 如果提供商只能接受 `appid` 查询参数，应在 HTTP 客户端、代理和日志系统中配置 URL 参数脱敏，并避免记录完整请求 URL。

2. **加强外部模型的数据边界**
   - 将模型端点、数据传输策略和允许发送的工作区范围配置化。
   - 在发送前增加结构化数据分类和更广泛的凭据识别，避免把整个工作区内容作为上下文发送。
   - 对高敏感任务提供本地模型或明确的“禁止外发”模式。

3. **降低工具结果的提示注入影响**
   - 为工具结果使用结构化字段和来源标签，而不是直接拼接自然语言。
   - 对每个工具声明最小权限、可访问路径和副作用。
   - 对写操作继续保持用户确认，并在执行前向用户展示目标文件、补丁摘要和变更范围。

4. **强化写操作授权**
   - 不要把模型生成的 `confirm=true` 视为用户授权。
   - 将确认令牌绑定到具体补丁摘要、会话和一次性操作，避免跨请求复用。
   - 对补丁涉及的文件数量、文件类型和单文件大小继续设置硬性上限。

5. **隔离子进程**
   - 在生产环境使用低权限运行账户、容器或操作系统级沙箱。
   - 限制子进程可访问的目录、网络和环境变量，并对超时、输出大小和退出状态进行审计。

6. **隔离会话状态**
   - 将状态机、对话消息和确认上下文从模块级全局变量改为每个会话独立的实例。
   - 若暂时保持单进程全局状态，应明确禁止并发请求，或在入口处增加串行化和会话标识校验。

## Residual Risk and Limitations

- `WEATHER_API_KEY` 仍可能因 OpenWeather 的接口约束出现在请求 URL 中，这是当前最明确的残余凭据暴露风险。
- 脱敏基于模式匹配，不能保证识别所有自定义凭据、编码后的秘密或业务敏感数据。
- 本审查未进行依赖及传递依赖漏洞扫描；项目当前没有锁文件。
- 未执行部署环境、操作系统权限、代理日志、TLS 终止点或远程模型服务端的配置审计。
- 本审查未将模型提供商视为可信边界；生产部署仍应依据组织的数据分类和供应商协议进行批准。
